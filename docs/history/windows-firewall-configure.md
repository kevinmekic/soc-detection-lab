## Historical creation error

`New-NetFirewallRule` reported "At least one address prefix is invalid" (HRESULT **0x80070057**). The subsequent query did not find **SOC-Lab-SMB-Block-IPv6**; the block ended with **Expected exactly three active lab rules**. The complete rule conditions were not printed. The readback at the time confirmed the two IPv4 rules in both stores. The block rule returned LocalAddress 0.0.0.0; the required source restriction was not completely accepted at the time. The state after the subsequent successful repair is described in the next section.

The earlier IPv6 rule contained `::/0` for both LocalAddress and RemoteAddress. The official definition of `FW_IPV6_SUBNET` requires prefix lengths **1 to 128**; the original documentation review had overlooked this restriction. This supports `::/0` as the cause of the parameter error. The error message does not name either of the two arguments specifically. [Microsoft specification](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fasp/ccb501eb-6620-4b49-befd-2b59828a28c8)

In addition, the block kept running despite `$ErrorActionPreference = 'Stop'`. Future NetSecurity calls therefore get `-ErrorAction Stop` explicitly; no unverified explanation of the module's internal behavior is claimed. The three backticks copied along at the end were a separate invalid PowerShell command and did not undo the rules that may have been created.
