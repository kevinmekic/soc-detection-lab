## How the output is assessed

| Section | Required statement and limit |
| --- | --- |
| Guest time / time zone | LocalTime and UtcTime describe the same instant with an explicit offset. Compare with the actual current Mac time. BaseUtcOffset is the base offset of the time zone, not necessarily the current daylight saving offset. No time is set. |
| ForceGuest | Present, RegistryKind and ValueJson preserve the actual state. For the experiment we need the **Classic** account model, so that the local account authenticates under its own identity. Missing, null or an unexpected type is not a silent 0. ForceGuest DWORD 0 was actually supplied; no repeated GUI query is needed. |
| SCENoApplyLegacyAuditPolicy | Only document an existing value. DWORD 1 prevents processing of the older audit category policies; the value alone does not prove complete event capture. Missing/0 is no reason to change a policy automatically now. |
| BadLoginCount | Actually Unavailable: the query returned a cache exception. Counter unknown, not a measured 0. For this bounded pilot, an explicitly confirmed quiet period over the known 10-minute reset window without test-account logon attempts, plus a freshly checked lockout state, is possible instead; no measured value is invented from it. The unsuccessful getter is not requested again. A single SMB request can cause several authentications. |
| IsAccountLocked | The pilot needs an actually returned Boolean false. A missing or unevaluable property is no confirmed unlock. The script unlocks nothing. |
| Installed-key product status | Determine the Windows Pro line from the actually returned Name/Description/LicenseFamily. LicenseStatus 1 technically means Licensed; GracePeriodRemaining is given in minutes. No matching line or several unclear products are not interpreted as activation. User confirmation of the own license and the technical status remain separate statements. Activation is no proof of the audit/SMB function and no reason to connect the isolated network to the Internet on one's own. |
| All active routes | Check the complete IPv4/IPv6 list with interface and NextHop: no unexpected default route, foreign gateway/network route or additional interface with an external path. The missing default route already observed does not by itself prove complete isolation. Loopback, the own host-only subnet and multicast entries are assessed by their actual meaning. |
| Per-user Audit Logon | Read the actual inclusion/exclusion settings for lab-auth01 including the exit code. The system-wide setting was Success and Failure; an account-specific exception can change this. No inclusion alone does not mean the system-wide audit is off; an effective exclusion has to be assessed separately. A failed query remains an open check. |

The WinNT query used DirectoryEntry.InvokeGet for documented IADsUser properties. The general provider support was no reliable evidence that BadLoginCount could be retrieved successfully this way in the actual guest; the real cache exception corrects the earlier source review. No Win32_UserAccount field of the same name or substitute value is invented. [IADsUser properties](https://learn.microsoft.com/en-us/windows/win32/adsi/iadsuser-property-methods), [WinNT provider support](https://learn.microsoft.com/en-us/windows/win32/adsi/provider-support-of-adsi-interfaces), [InvokeGet](https://learn.microsoft.com/en-us/dotnet/api/system.directoryservices.directoryentry.invokeget?view=windowsdesktop-10.0). The alternative quiet period follows the [reset policy](https://learn.microsoft.com/en-us/previous-versions/windows/it-pro/windows-10/security/threat-protection/security-policy-settings/reset-account-lockout-counter-after) and does not replace a measured counter.
